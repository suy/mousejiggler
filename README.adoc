A small system tray application that jiggles the mouse at regular intervals,
making the computer seem not idle. Sits passively on your system tray, and
allows some settings to be configured to the needs of the user. It also features
an "invisible" mode that doesn't move the cursor, but still produces synthetic
events.

It's a native {cpp}/Qt GUI application that preserves your settings across
launches, but also supports overriding options by launching it from the
terminal.

It tries to provide a familiar (but improved) experience to a different
https://github.com/arkane-systems/mousejiggler[mouse jiggler] that the author was
using before, but grew frustrated with due to lack of some small features and
annoying defaults.

== Platform support

For now, Windows only. I've only needed this on Windows, but I'm also a Linux
user, so adding support for Linux is on the table if I ever need it (not too
likely) or someone provides a patch. Note that the code is mostly
cross-platform, but the details of moving the cursor are often annoying to
implement well, and it's platform specific. Ideas for how to implement this on
Wayland are very welcome.



== Synopsis

After installing and starting the app:

* The mouse pointer will start making small movements at periodic intervals.
* The default is a lateral movement of only 1 pixel each 60 seconds.
* If you moved the cursor in those 60 seconds, the app won't move it, to prevent
  disturbing you. On the next interval it will check again if the mouse was
  moved since the previous "tick" of the clock.
* Configure the interval duration and the patterns to your liking.
* Dismiss the window to the system tray by closing it, or pressing kbd:[Ctrl+W].
* Toggle jiggling with the checkbox or kbd:[Ctrl+T].
* Close the app entirely via the right click menu or kbd:[Ctrl+Q].



== Jiggle modes

[cols="1,3"]
|===
|Mode     |Movement

|Linear   |Slides left and right, without vertical movement (the default).
|Diagonal |Slides diagonally: moves right and down, then left and up.
|Circle   |Moves around a small circle.
|Invisible|Sends input events that can reset idle detection without moving the cursor.
|===



== Multiplier

The movement pattern in the different modes are as small as possible. For
example, the linear one is just one pixel left, one right (and repeat). The
multiplier just scales that movement to make it bigger. That's it.



== Randomized time

If interval randomization is enabled, the time to trigger jiggles will be picked
at random between 1 and the number of seconds specified.



== Command line

The command line options allow changing the initial values for a first time use
(or if you removed the settings data for your system). These options also allow
changing the settings that were saved from the last time the application was
used. This allows control of the application entirely with the keyboard, with
shortcuts, macropads, etc.

Note that the command line values not only override the persisted settings from
the previous session, but also set them for the next one. The options:

[cols="1,3"]
|===
|Option
|Description

|`-j`, `--jiggle`
|Start with jiggling enabled (the default).

|`--no-jiggle`
|Start with jiggling disabled. The app will remain passive until you enable
jiggling again. This is ignored if `--jiggle` is passed.

|`-m`, `--minimized`
|Start hidden in the system tray (the default).

|`--show-window`
|Start with the settings window visible.

|`-o`, `--mode <mode>`
|Jiggle mode: `linear` (the default), `diagonal`, `circle` or `invisible`.
Linear will move the pointer left and right, back and forth. Diagonal will move
at once left and up or right and down. Circle will move in a tiny circle. And
invisible won't move the cursor, but it will try to still send events to prevent
the operating system from sleeping.

|`-s`, `--seconds <n>`
|Jiggle interval in seconds (1 to 3600).

|`-r`, `--random`
|Randomize the jiggle interval. Each "tick" of the timer will pick at random one
value in seconds from 1 to the interval specified.

|`-d`, `--distance <n>`
|Distance multiplier (1 to 100). This will make the movements larger, instead of
as small as possible, which is the default (that is, 1 pixel).
|===


[TIP]
====
On Windows the program is a GUI application, and those never attach to the
console they are launched from: the console belongs to the shell, and Windows
does not share it with GUI programs. The help, the version and the command line
errors are then shown in a GUI message box, with unfortunate formatting due
to the proportional font.

To get the text in your console, pipe or redirect the output, which makes the
shell hand the program real standard handles:

----
mousejiggler.exe -h | Out-String    # PowerShell: prints it in the console
mousejiggler.exe -h > help.txt      # any shell: writes it to a file
----

Setting the `QT_COMMAND_LINE_PARSER_NO_GUI_MESSAGE_BOXES` environment variable
(e.g. with `$env:QT_COMMAND_LINE_PARSER_NO_GUI_MESSAGE_BOXES = '1'`) silences
the message box, but then the output goes to the nonexistent console, so
you will only see it if you redirect it.
====



== Building

Requires Qt 6, with the widgets module. Qt 5 is probably supported as is, but I
don't necessarily will support it in the future. The build system is qmake:

----
mkdir build && cd build
qmake ../mousejiggler.pro
make
----



== Architecture

The application is so simple, that I've not bothered implementing unit tests
for its internals. The single-instance behavior is the exception: it has
process level tests under `tests/auto/`, which spawn the real application
binary and observe it from the outside. I tried to structure the rest in a way
that it's simple enough to understand, review and test.

* `src/jiggler.{h,cpp}`: the jiggling logic. A `Jiggler` object owning the
  timer, the movement patterns and the persisted settings. No Widgets
  dependency, so an alternative frontend (for example QSkinny) can drive
  it later.
* `src/mainwindow.{h,cpp}`: the Qt Widgets frontend. Settings window and
  system tray integration. It knows nothing about the jiggling logic: it
  emits value-only signals for user actions and receives state updates
  through its public slots. The countdown to the next jiggle is an
  approximation driven by an own one-second timer, re-synchronized whenever
  the logic reports the next interval.
* `src/platform.{h,cpp}`: platform abstraction. Relative mouse movement
  injection and stay-awake control. The Windows implementation does the real
  work. Other platforms get stubs so the application builds and runs for
  development. The variant is selected per function with the preprocessor, so
  both implementations read in one file.
* `src/app.cpp`: the integration point. Creates the logic and the
  interface as independent objects and connects them. Values crossing the
  boundary in both directions via signals and slots connected here. Also owns
  command line parsing and the single-instance guard.
